# Native catalog, reading 8 (2026-10-17)

## 0. What this is {#what-this-is}

This is the native catalog's eighth milestone report. It is also a
reading: it measures each success measure on one master commit,
`612831d`, which merged on 2026-10-16 at 20:55 UTC. The previous report is
[reading 7](2026-10-16-reading-7.md), on the master commit `f54ddab`,
which merged on the same day at 04:58 UTC. A name such as T47 names one of
the native loop's tickets ([`tickets.md`](../tickets.md)), and a number
such as #501 is a PR.

The trigger of this report is "KPI crosses a mark", one of the triggers
that [`reporting.md`](../../reporting.md) lists. A KPI (key performance
indicator) is one of the numbers in the block at the start of each report.
For the native loop, the KPI `coverage_native` crosses a mark when a whole
sklearn module goes native. T47 (#501) made `sklearn.cluster` wholly
native. Of the five classes of the module in scope, `FeatureAgglomeration`
was native before, and T47 serves the other four: `KMeans`,
`MiniBatchKMeans`, `BisectingKMeans` and `Birch`. Since reading 7, the
native coverage went from 41 to 48 of the 68 sklearn classes in scope. The
catalog's contract
([`catalog-contract.md`](../../../packages/sql-transform/spec/native/catalog-contract.md))
puts a class in scope if its `transform` maps one row of features to one
row of outputs, and uses only the fitted state ([section 2](#scoreboard)).

**Terms of this report:**

- A *class* is an sklearn class, such as `PCA`. In this report, the word
  never means the glossary's class, a group of findings.
- A *step* is one fitted sklearn transformer, which its twin
  (`PythonTransform`) serves. A step holds one or more fitted *instances*
  of its class, each under its own integer *instance id*, such as 0 or 1.
  Each row carries the instance id of the instance that serves it.
- A *composition* is a step that combines other steps: a `Pipeline`, a
  `ColumnTransformer` or a `FeatureUnion`. The steps that a
  `ColumnTransformer` or a `FeatureUnion` combines are its *parts*. Its
  parameter `transformer_weights` can give a part a weight, which
  multiplies the part's output.
- The catalog's tests draw their steps from *fixture configurations*,
  the configurations of each class that the tests list
  (`catalog_test.FIXTURES`). A *configuration* is one set of a class's
  parameters. A *seed* selects one generated case. Here a case is one step
  of a configuration and its rows. The seed sets the random data of
  sklearn's fit and of the rows.
- `to_native` is the catalog's function that translates a step into its
  catalog entry. If the entry does not serve the step, `to_native` raises
  `NotNative`, and the step *stays Python*: its twin serves it. A step with a parity bound above 0 serves
  only if the caller asks for a bound: `to_native(step, allow_bound=True)`.
- `to_native` builds the entry's query once with confit, to check that
  confit accepts it: this is the *trial build*.
- A *translator* is the part of an entry that turns one fitted step into
  the expressions of its output fields.
- The *input guard* of an entry traps on each row where the twin raises
  an error. To build the guard, `to_native` sets each feature in turn to
  NaN, NULL or an infinity, calls the twin on that row and notes where
  the twin raises an error. This procedure is the *probe* (finding 84,
  [section 5](#findings)).
- A family whose builds can take long estimates the time of the trial
  build from the step's size, such as its numbers of features, components
  or output fields. Some families estimate the time of the whole
  `to_native` instead (finding 92, [section 5](#findings)). The estimate
  is a formula, and the native loop fits its coefficients to measured
  times. The *cap* of the family keeps a step Python if its estimate is
  above 7 s. The cap *takes* a step whose estimate is 7 s or less, so that
  `to_native` builds the step's entry.
- A *warm* `to_native` or build is one that runs after an earlier one in
  the same process, so it does not pay the first imports and setup.
- The *parity run* is one run of the catalog's parity test over 200 seeds
  of every fixture configuration ([section 4](#exactness)).
- This report names four groups of the classes with an error scale
  ([section 4](#exactness)). The *linear projections* are `PCA`,
  `IncrementalPCA`, `TruncatedSVD` and `GaussianRandomProjection`. The
  *centered projections* are `FastICA`, `LinearDiscriminantAnalysis` and
  the four PLS classes (partial least squares): `PLSRegression`,
  `PLSCanonical`, `CCA` and `PLSSVD`. The *distances to fitted centres*
  are the `transform` of `KMeans`, `MiniBatchKMeans`, `BisectingKMeans`
  and `Birch`. The *kernel samplers* are `AdditiveChi2Sampler`,
  `RBFSampler` and `SkewedChi2Sampler`, in `kernel.py`.
  `AdditiveChi2Sampler` maps each feature to 2·`sample_steps` − 1 output
  fields: one field at sample point 0, and a cos and a sin field at each
  sample point j from 1 to `sample_steps` − 1.
- A *call* serves a batch of rows, each row one request. A *native* call
  is a call that the entry serves. The *width* of a step is its number of
  output fields.
- The *bench* (`benchmarks/bench_native.py`) times the widest step of each
  class: its build, and calls of 64 rows, native and twin
  ([section 3](#speed)).
- A *shared value* is a value that confit computes once for each row and
  reads many times. A *node* is one operation, column or constant of an
  expression. Confit counts the nodes of an expression as written, after
  it writes `coalesce(x, NaN)` as `CASE WHEN x IS NULL THEN NaN ELSE x
  END`. The pass of confit that finds shared values (`share.rs`) shares a
  value only if both of these hold: the value has six nodes or more, and
  it cannot raise an error.
- Since T44 (#498), the catalog reads each number feature x as
  `coalesce(x, NaN) - 0.0`. A *number feature* here is any feature that is
  not a string, and the catalog reads a boolean as the double 0 or 1. The
  read gives the same double as x, with NULL read as NaN, because
  subtracting 0.0 changes no double. It has seven nodes
  and cannot raise an error, so confit shares it. Before T44, the catalog
  read `coalesce(x, NaN)`, which has five nodes, so confit computed it
  again at each read (finding 85, [section 5](#findings)). This report
  calls them *T44's reads* and the *reads before T44*. A projection and
  `RBFSampler` keep the reads before T44 if their estimate with T44's
  reads is above 7 s. In the code, `project._reads_apart` and
  `kernel._rbf_reads_apart` make this choice: `project.py` holds the
  projections, and `kernel.py` the kernel samplers.
- A script name such as `caps_r8.py` names a script of this reading, in
  the project's shared folder ([section 8](#environment-and-repro)).

## 1. What moved {#what-moved}

**Seven more classes serve within a parity bound, and the coverage is 48
of 68.**
- The coverage is the number of the 68 sklearn classes in scope that
  have a catalog entry ([section 2](#scoreboard)). It was 41 at reading 7.
- T47 (#501) serves `KMeans`, `MiniBatchKMeans`, `BisectingKMeans` and
  `Birch`. The `transform` of each gives the distance of the row to each
  fitted centre. `sklearn.cluster` is now wholly native
  ([section 2](#scoreboard)).
- T49 (#503) to T52 (#506) serve three of the five kernel samplers of
  `sklearn.kernel_approximation`: `AdditiveChi2Sampler`, `RBFSampler` and
  `SkewedChi2Sampler`. A kernel sampler maps a row to features whose
  products approximate a kernel.
- Each output field of these entries is within K·eps·S + τ of the twin,
  where S is the error scale of the field and n the number of features
  ([section 4](#exactness)). For the distances to fitted
  centres, K is n + 5, and the bound compares the squares of the
  distances. `AdditiveChi2Sampler` is bit-exact with
  `sample_steps=1`, and within K = 4 with more steps. For `RBFSampler`, K
  is n + 3, and for `SkewedChi2Sampler`, n + 4.
- This reading ran the measurements of T47, T50, T51 and T52 again. In
  them, the largest value of |entry − twin| / (eps·S), on the squares for
  the distances, is 7.39, for `Birch` at 64 features, where K is 69. The
  room of a value is K divided by the value, so this value has a room of
  9.3. The least room is 2.51, for `MiniBatchKMeans` at 2 features, where
  K = 7 and the value is 2.79.
- These entries serve only if the caller asks for a bound:
  `to_native(step, allow_bound=True)`.
- At their widest steps of the bench, the four classes of the distances
  to fitted centres serve a call of 64 rows in 88 to 276 µs, 96 to 297 times as fast as their
  twins. `RBFSampler` serves 17 times as fast as its twin,
  `AdditiveChi2Sampler` 6.6 times and `SkewedChi2Sampler` 2.8 times
  ([section 3](#speed)).

**A step with a parity bound now serves inside a composition (T42,
#495).**
- With `allow_bound=True`, such a step serves as the last step of a
  `Pipeline`, or as a part of a `ColumnTransformer` or `FeatureUnion`, if
  `transformer_weights` has no entry for that part. This is option 1 of
  the owner's ruling on bounded steps in compositions
  ([bounded-steps-in-compositions.md](../decisions/closed/bounded-steps-in-compositions.md)).
  The other positions that the ruling allows are open work
  ([section 7](#left-open)). `native.check`, the function that compares
  an entry with its twin, holds each output field of the composition to
  the bound of the step inside it that computes the field.
- The parity run has 10 configurations of such compositions. It compared
  1,969 of their 2,000 steps with their twins, with no failure. The other
  31 stay Python. In them, the part `FunctionTransformer(np.exp)` reads
  boolean features only. Over booleans, numpy's `exp` answers in float16,
  so this part stays Python, as the step alone does
  ([section 4](#exactness)).

**The catalog reads each number once a row, and many steps serve faster
(T44, #498, and T45, #499).**
- Since T44, a translator reads each number feature as `coalesce(x, NaN) -
  0.0`, which confit computes once a row. Before T44, confit computed the
  input guard's `coalesce(x, NaN)` again at each read (finding 85,
  [section 5](#findings)). [Section 0](#what-this-is) gives both reads.
- Since T45, `KBinsDiscretizer` with ordinal bins finds the bin of a
  value by bisection over the bin edges.
- This reading ran the bench three times at master and twice at reading
  7's commit `f54ddab` on this machine, alternating between the two
  commits. In the bench, 14 classes
  serve faster at master than in both runs of `f54ddab`.
  `SplineTransformer` serves a call in half the time of the faster run of
  `f54ddab`. `KBinsDiscretizer`,
  `QuantileTransformer`, `PCA`, `IncrementalPCA`, `IsotonicRegression` and
  `PowerTransformer` serve a call in 0.77 to 0.89 times the time of the
  faster run ([section 3](#speed)). A search over the commits of T43 to
  T46 ties most of these changes to T44. From T44 on, each run of
  `SplineTransformer`, `QuantileTransformer`, `PCA` and `IncrementalPCA`
  serves faster than each run before T44.
- The width curves time steps of one class at growing widths
  ([section 3](#speed)). In them, 21 steps of `SplineTransformer`,
  `KBinsDiscretizer` with ordinal bins, `QuantileTransformer`,
  `IsotonicRegression`, `PCA` and `OrdinalEncoder` over number features
  serve a row 1.4 to 4.3 times as fast as at `f54ddab`. `KBinsDiscretizer`
  of 32 features with 31 ordinal bins
  serves a row in 5.27 µs, against 22.46 µs. At 256 features of 64
  components, `PCA` serves a row in 17.7 µs, against 41.0 µs, and now as

**Builds near the caps take 0.71 to 1.34 times their estimates, against
1.02 to 1.51 at reading 7.**
- T46 (#500) fitted the coefficients of the estimates of
  `RandomTreesEmbedding` (a forest), of `IsotonicRegression`, of
  `QuantileTransformer` and of `SplineTransformer` again on T44's reads.
  T47, T51 and T52 fitted the estimates of their families. The
  projections have two estimates: one for a step whose products of a
  feature and a coefficient read a shared value, and one for the reads
  before T44. T48 (#502) gave both a term in n², for n features (finding
  87, [section 5](#findings)). Before T48, the cap took
  `FastICA` of 2 components over 4,096 features, which built with a list
  output in 11.7 s, past the cap of 7 s. Now the cap keeps it Python.
- The slowest build of a step that a cap takes is 7.30 s, for
  `SkewedChi2Sampler` of one feature and 768 components, against 9.2 s at
  reading 7 ([section 3](#speed)).
- T46's estimates estimate the trial build alone. The estimates of T47,
  T48, T51 and T52 estimate the whole `to_native`, which includes the
  probe (finding 92, [section 5](#findings)). So in T46's families, the
  cap of 7 s bounds the
  trial build alone. In the other families, it bounds the whole
  `to_native`.

**Bad news.**
- The entry of `AdditiveChi2Sampler` has no build estimate, so no cap
  keeps its slow builds Python (finding 91, [section 5](#findings)). With
  `sample_steps=3` over 256
  features, `to_native` takes 28.5 s, against the 7 s of every cap. The
  next ticket gives this entry an estimate and a cap
  ([section 7](#left-open)).
- `SkewedChi2Sampler` serves only 1.2 times as fast as its twin at 32
  features of 64 components, and its widest step of the bench serves 2.8
  times as fast. With n features and m components, each of the m output
  fields sums n products, and each product reads the logarithm of one
  feature. Confit computes the logarithm of a feature again in each of
  the m output fields: n·m logarithms a row, where the twin computes n
  (finding 90, [section 5](#findings)). Confit computes a shared value
  once, before the first expression that reads it. It computes the value
  even on a row where the branch of the SQL CASE expression that reads it
  is not taken. If the value raised an error, it
  would raise on that row, where the query does not. So confit shares
  only a value that cannot raise an error, and `ln` can raise. This is a
  new need of the catalog from confit (need 5,
  [section 6](#needs-from-confit)).
- With T44's reads, a forest of `RandomTreesEmbedding` over many
  features builds more slowly. So the cap no longer takes some forests
  that it took before. Over 128 features, it now takes a forest of up to
  about 5,200 output fields, against 6,800 before T44 (T46's estimate in
  `trees.py`, the forests' module). On `612831d`, 100 trees of depth 5
  over 128 features build with a list output in 1.10 s, against 0.59 s
  with the reads before T44 (`forest_ab.py`, T46's script). They serve a
  row in 105.2 µs with T44's reads, against 115.2 µs with the reads
  before T44. So T44's reads build more slowly but serve faster. An item of PLANS "Later" would let such a
  forest keep the reads before T44, as a projection does
  ([section 7](#left-open)).
- T50's measurement of `AdditiveChi2Sampler` cannot be repeated to the
  last digit. Its script computes the seed of its rows with Python's
  `hash` of a string, and that hash changes in each process. So the run of
  this reading drew other rows. Its largest value is 1.42, against 1.96 in
  T50's own run, and both are within K = 4 ([section 4](#exactness)).

**The error scales.** The error scale S of an output field adds the sizes
of the operations whose rounding can differ between the entry and its
twin. The bound is |g(entry) − g(twin)| ≤ K·eps·S + τ. Here g is a map that
the family applies to both answers before it compares them, such as the
square. It is the identity unless the family names another map. For output field k of a row x,
with n features:

| family | classes | g | S | K | τ |
|---|---|---|---|---|---|
| linear projections (T37, `project.py`) | `PCA`, `IncrementalPCA`, `TruncatedSVD`, `GaussianRandomProjection` | identity | (Σ_i \|x_i·c_ki\| + Σ_i \|m_i·c_ki\|) / s_k | n + 3 | (2n/s_k + 1)·2^-1074 |
| centered projections (T41, `project.py`) | `FastICA`, `LinearDiscriminantAnalysis`, `PLSRegression`, `PLSCanonical`, `CCA`, `PLSSVD` | identity | Σ_i \|d_i·c_ki\| | n + 1 | 2n·2^-1074 |
| distances to fitted centres (T47, `distance.py`) | `KMeans`, `MiniBatchKMeans`, `BisectingKMeans`, `Birch` | the square | ‖x‖² + ‖c_k‖² + 2·Σ_i \|x_i·c_ki\| | n + 5 | 4n·2^-1074 |
| `AdditiveChi2Sampler` (T50, `kernel.py`), `sample_steps` of 2 or more | `AdditiveChi2Sampler` | identity | f·(1 + \|j·s·ln x\|) for the cos and sin fields of feature x at sample point j, for j from 1 to `sample_steps` − 1 | 4 | 2^-1074 |
| `RBFSampler` (T51, `kernel.py`) | `RBFSampler` | identity | a·(Σ_i \|x_i·W_ik\| + \|b_k\| + 1) | n + 3 | 0 |
| `SkewedChi2Sampler` (T52, `kernel.py`) | `SkewedChi2Sampler` | identity | a·(Σ_i \|L_i·W_ik\| + \|b_k\| + 1), with L_i = ln(x_i + `skewedness`) | n + 4 | 0 |

The terms of the table:

- c_ki is the coefficient of feature i in component k. m_i is the mean of
  feature i, which is 0 for `TruncatedSVD` and `GaussianRandomProjection`.
  s_k is the whitening scale of component k under `whiten=True`, else 1.
  d_i is the feature after the centered projection subtracts its mean, and
  divides by its scale where the class has one
  ([reading 7](2026-10-16-reading-7.md#exactness), section 4).
  2^-1074 is the smallest positive double.
- For the distances, c_k is centre k, and the family compares the squares
  of the two distances. Near a centre, the true square is close to 0, but
  each side computes it with an error of about eps·S. Each side then
  takes the square root of its square. So the two distances can be about
  sqrt(eps·S) apart, and no small bound holds for the distance itself. Item 3 of the ruling on the
  parity bound
  ([matvec-parity-bound.md](../decisions/closed/matvec-parity-bound.md))
  compares the squares instead, within K = n + 5.
- For `AdditiveChi2Sampler`, s is the sample interval, and f =
  sqrt(2·x·s / cosh(π·j·s)). The entry computes the twin's operations in
  the twin's order. The translator computes the twin's `cosh(π·j·s)` with
  numpy and writes the value into the SQL as a constant.
  So the entry differs from the twin only where confit's `ln` differs
  from numpy's `log`. The kernel probe measures that difference (the last
  paragraph of this section). The field of sample point 0, sqrt(x·s), is
  bit-exact.
- For the two other samplers, W is the matrix of random weights, b the
  random offsets, and a = sqrt(2/m) for m components. Each output field
  is a times a cosine. A product that underflows errs by at most
  2^-1075, far below eps·a, so τ is 0.

The reason for each bound is the twin's arithmetic, which SQL cannot
follow:

- The projections and the samplers multiply the row by a matrix with
  BLAS, numpy's linear algebra library, which adds the terms in an order
  that depends on the CPU. The entry adds the products in pairs, then the
  pair sums in pairs, and so on.
- The distances follow numpy's float64 path, sqrt(max((−2·(x·c) + ‖x‖²) +
  ‖c‖², 0)), with the same pairwise sums.
- `AdditiveChi2Sampler` and `SkewedChi2Sampler` use numpy's `log`. On a
  machine with AVX-512, this is the vector code of Intel's Short Vector
  Math Library (SVML), up to 1 ulp from the `log` of glibc, which the
  oracle and confit call. `RBFSampler`, `AdditiveChi2Sampler` and
  `SkewedChi2Sampler` use numpy's `cos` (and `sin`), which the kernel
  probe measures as equal to glibc's on this machine. Where a kernel probe reads more
  than 1 ulp for `log`, or more than 0 for `cos` or `sin`, the step stays
  Python.

The docstrings of `project.py`, `distance.py` and `kernel.py` derive each
K from the rounding error of each operation, as item 1 of the ruling
asks: each family derives K from the error bounds of its operations.

## 6. Needs from confit {#needs-from-confit}

A need is a capability that the native loop asks the confit loop to make
in confit. Each need has a short name in backticks, which the KPI block
lists under `needs_from_other_loop` while the need is open.

**Delivered since reading 7:** none. The owner paused the confit loop on
2026-10-16, before `f54ddab`, the commit that reading 7 measured. The
confit loop merged no PR since. So confit's code on `612831d` is the code

**Open:** five needs. Needs 1, 3 and 4 below are reading 7's needs 3, 4
and 5. Needs 2 and 5 are new. This reading measured each of them on `612831d`, with
the reproductions in the project's shared folder
`/mnt/project-files/transforms-loop/`. A reproduction uses confit alone,
without the catalog's code.

1. **A struct output read field by field, built once for the call**
   (`struct-field-reads`, the rest of finding 60). Confit builds each field
   read of a struct output on its own. With confit alone,
   a struct of 4,000 fields builds in 0.64 to 0.71 s read field by field,
   and in 0.33 to 0.34 s read whole (`confit-field-reads-456.py`, a
   reproduction of confit #456). At reading 7, it built in 0.66 to 0.74 s
   read field by field, and in 0.33 to 0.39 s read whole. In the catalog,
   100 trees of depth 5 build in 0.76 to 0.87 s as a struct read field by
   field, and in 0.36 to 0.44 s as a list. 250 trees of depth 5 build in
   2.78 to 2.89 s as a struct, and in 1.09 to 1.14 s as a list. So the
   struct takes 1.7 to 2.4 times the time of the list at 100 trees, and
   2.4 to 2.7 times at 250 trees. At reading 7, it took 1.6 to 2.4 times
   ([section 3](#speed)).
2. **Deep expressions** (`deep-expressions`, finding 86). Confit's parser
   refuses SQL that nests about 512 additions deep, and confit's
   `SqlFunction` writes the SQL of a shared value by recursion in Python.
   On `612831d`, `to_native` raises `NotNative` for
   `Normalizer(norm="l2")` from 512 features, so the step stays Python (`deep_r8.py`):
   - At 512 features, confit refuses the SQL function of the step after
     5.4 s. Expanded, the function passes 4,000,000 tokens of SQL, confit's
     limit on the size of a function.
   - At 1,024 features, confit's parser passes its recursion limit.
   - At 2,048 features, the catalog's own SQL passes Python's recursion
     limit. Since T48, `to_native` raises `NotNative` there, not
     `RecursionError`.

   Of the entries measured, only `Normalizer(norm="l2")` nests so deep.
   The entries with an error scale add their n terms as a balanced tree,
   log2(n) deep, for n features.
3. **A named refusal, not a Cranelift verifier error**
   (`verifier-error-refusal`, finding 63). Cranelift is confit's code
   generator. Cranelift's verifier checks the code that confit generates.
   On a wide `OneHotEncoder`, the verifier once stopped with an internal
   error, and confit gave no refusal. On `612831d`, the reproduction
   (`confit-wide-encoder-verifier.py`) does not raise the error, as at
   readings 6 and 7. `to_native` translates its step, and the whole run
   takes 4.4 s. No step that this reading measured raises the error
   either.
4. **A cheaper pass over a function body in Python**
   (`function-body-pass`, finding 72). With confit alone, confit's
   pass over the body of a SQL function, in Python (`SqlFunction`), takes
   0.70 s for a balanced CASE tree of 8,000 leaves, against 0.68 s at
   reading 7. So the pass is as slow as at reading 7. The build and one
   call take 2.52 s, against 2.62 s. This need has a low priority.
5. **A logarithm computed once a row** (`shared-logarithm`, finding 90).
   Confit computes a value once a row only if the value cannot raise an
   error. It judges this node by node, without the conditions of the CASE
   around the node. `ln` raises an error on a number of 0 or less, so
   confit never shares it, even where a CASE keeps such numbers away. So
   for n features and m components, the entry of `SkewedChi2Sampler`
   computes n·m logarithms a row, not n. T52's script
   (`variants_serve.py`) serves a step of 32 features of 64 components, in
   calls of 64 rows:
   - With the entry's `ln`, a list return serves a call in 6,531 µs, where
     its twin takes 12,522 µs. A struct return serves a call in 11,435 µs,
     where its twin takes 18,754 µs.
   - With `exp` in place of `ln`, which confit shares, the list serves a
     call in 776 µs and the struct in 775 µs. Their twins take 11,836 and
     16,856 µs. This variant gives other values than the twin, so it only
     times a function that confit shares.
   - So a logarithm computed once a row may serve the list in 0.12 times
     the time of the entry's `ln` (776 against 6,531 µs), and the struct
     in 0.07 times (775 against 11,435 µs).
